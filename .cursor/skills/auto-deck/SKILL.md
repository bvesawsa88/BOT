# เช็คออโต้เด็ค

ผู้ใช้ส่งทั้งเด็คมาครั้งเดียว แยกงานเป็น 2 ชั้น: **เช็คกติกาก่อน** แล้ว **ทำออโต้ทีละชุด** อย่าทำกลไกใหม่ทั้งเด็คในรอบเดียว

## ทริกเกอร์

ใช้สกิลนี้เมื่อข้อความมีอย่างใดอย่างหนึ่ง:

- `# Main Deck` / `# Life Deck` / `Nx CODE` (เช่น `4x BT09-042-UR`)
- คำว่า เช็คออโต้, ออโต้เด็ค, เช็คเด็คนี้
- รายการเด็คกำหนดเองที่ต้องการให้เล่นออโต้ได้

ถ้าส่งใบเดียวหรือบอกว่าใบนี้พัง ให้แก้ใบนั้น ไม่ต้องรันไพป์ไลน์ทั้งเด็ค

## ขั้นที่ 1 — แปลงรายการ

- ตัดความหายากท้ายรหัส: `BT09-042-UR` → `BT09-042`
- รวมจำนวนต่อรหัส (`4x` = 4)
- หาชื่อ/ประเภทจาก `data/cards.json` (นับลิมิตต่อ**ชื่อ** ไม่ต่อรหัส)
- รหัสไม่มีในฐาน = รายงานทันที อย่าเดา

## ขั้นที่ 2 — เช็คกติกา

ยึด `js/carddb.js` (`isOnly`, `limitOf`) + `data/banlist.json`:

| กฎ | ผ่านเมื่อ |
|---|---|
| Main | รวม 50 ใบ |
| LIFE | รวม 5 ใบ ประเภท Life |
| ต่อชื่อ | ≤4 เว้น Only / banlist |
| Banned | ใส่ 0 |
| Limit 1 / 2 | สูงสุด 1 / 2 ต่อชื่อ |
| Only #1 | เด็คมีได้ 1 ชื่อ Only (เว้น `customLimit` เป็นตัวเลข) |

รายงานผลกติกาก่อนลงมือเขียนเอฟเฟกต์

## ขั้นที่ 3 — แยกใบออโต้

เทียบแต่ละรหัสไม่ซ้ำกับ `data/effects-all.json`:

| สถานะ | ความหมาย |
|---|---|
| `auto` / `verified` และมี `abilities` | มีแล้ว ข้าม |
| `abilities: []` / `manual` / ไม่มีใน effects | ต้องทำ |
| มี abilities แต่ op ใหม่ที่เอ็นจินยังไม่รองรับ | ต้องทำ + แตะ `js/engine.js` |

จัดชุดทำ: ใบที่**กติกาชุดเดียวกัน** 1–3 ใบต่อชุด เช่น นักท่องทั้งหมด → ใบที่ถูกอัญเชิญ → Skill React

รายงานตารางสั้นๆ:

```
กติกา: ผ่าน / ไม่ผ่าน (เหตุผล)
มีออโต้แล้ว: CODE ชื่อ
ต้องทำ (รีใช้ op เดิม): ...
ต้องทำ (กลไกใหม่ — ช้า): ...
ชุดแรกที่จะทำ: ...
```

แล้วลงมือชุดแรกทันที อย่าไล่อ่าน `engine.js` ทั้งไฟล์ก่อนมีตารางนี้

## ขั้นที่ 4 — ทำทีละชุด

ต่อชุด:

1. อ่านข้อความเอฟเฟกต์จาก `cards.json` ของใบในชุดนั้น
2. หา op / trigger ที่มีอยู่แล้วใน `js/engine.js` — รีใช้ก่อน
3. ถ้าต้องมี op ใหม่ ให้เพิ่มเฉพาะชุดนี้ ใน `js/engine.js` (และ `js/game.js` เฉพาะเมื่อต้องมี UI) โดยเลียนแบบ op ใกล้เคียง อย่าเขียนสคริปต์ไป string-replace เอ็นจิน
4. ใส่เอฟเฟกต์ลง `data/effects-{set}.json` (`parseStatus: "auto"`) ผ่าน `tools/apply-*-effects.js` แบบ `tools/apply-story-effects.js`
5. รัน `node tools/rebuild-abilities.js` (อัปเดต `data/abilities/*` + `data/effects-all.json`)
6. เขียน `tools/_test-{theme}.js` โฟกัสชุดนี้ รันให้ผ่านก่อนขึ้นชุดถัดไป

อย่าเริ่มชุดถัดไปถ้าชุดปัจจุบันยังเทสไม่ผ่าน  
อย่าดึงใบนอกเด็ค / งานอื่นเข้ามาในรอบเดียวกัน  
อย่า commit จนกว่าผู้ใช้จะขอ

## ขั้นที่ 5 — ใส่เด็คให้เลือกได้

เมื่อกติกาผ่าน เพิ่ม/อัปเดต `data/custom-decks.json`:

```json
"ชื่อเด็ค": {
  "name": "ชื่อเด็ค",
  "label": "ชื่อเด็ค (50+5)",
  "main": { "BT09-042": 4 },
  "life": { "BT01-051": 1 }
}
```

ใส่ได้หลังเช็คกติกา แม้เอฟเฟกต์ยังทำไม่ครบทุกชุด

## ตอนจบแต่ละรอบ

บอกชัด:

- ชุดที่ทำเสร็จ + เทสผ่าน
- ใบที่ยังค้าง (ชุดถัดไปคืออะไร)
- ถ้าเหลือกลไกใหม่ ให้ทำชุดนั้นต่อในแชทเดียวกัน ทีละชุด จนครบ หรือหยุดเมื่อผู้ใช้บอกพอ

## ห้าม

- สำรวจทั้งรีโป / อ่าน `engine.js` เป็นพันบรรทัดก่อนมีตารางแยกใบ
- ทำ 4+ กลไกใหม่พร้อมกัน
- สรุปว่าเสร็จทั้งเด็คทั้งที่ยังมีใบ `abilities: []`
- สับสนงานออโต้เด็คกับความช้าของแอนิเมชันในเกม
